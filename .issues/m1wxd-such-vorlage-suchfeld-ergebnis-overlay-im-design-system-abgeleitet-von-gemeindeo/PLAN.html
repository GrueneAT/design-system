01Strategy

Strategy summary

Distill the generic search behaviour out of the Gemeindeordnung reference and lift it into the design system, engine-neutral: a new .gat-search* CSS family plus one ESM module gat-search.js, shipped like gat-charts.js from the Pages URL. Strictly additive minor release v2.3.0 — no breaking changes.

  • Compose on existing primitives.

    .gat-input for the field, .gat-modal (native <dialog>) for the modal — only the .gat-search* family and the behaviour module are net-new.

  • Engine-neutral core, optional Pagefind adapter.

    The module knows no search engine — it takes an async (query) => results[] adapter and a slot schema. A documented Pagefind adapter ships as an optional example.

  • A11y is net-new, not ported.

    Arrow-key navigation, ARIA combobox/listbox/ option, focus-trap and prefers-reduced-motion are hard acceptance criteria absent from the reference.

Two locked variants in v1: an inline overlay dropdown that takes no flow space (no layout shift — fixes the werkzeuge symptom) and a modal / Strg+K variant reusing .gat-modal.

03Decisions

Key decisions & options

Modal base: native <dialog> vs. custom backdrop

Chosen

Keep native <dialog> / showModal() (= .gat-modal): top-layer, focus-trap, ESC and inert background for free. gat-search.js solves the one gap — returnFocus to the triggering element on close.

A custom backdrop like the reference — would duplicate the DS modal shell to avoid the focus-loss the module already handles.

Where debouncing happens

Chosen

gat-search.js owns debouncing (configurable) with a generation guard; the Pagefind adapter calls debouncedSearch(q, opts, 0). No double debouncing.

ARIA navigation model

APG

aria-activedescendant (focus stays in the input) over roving tabindex — the APG combobox-with-listbox pattern; net-new vs. the reference.

Locked decisions (CONTEXT.md)

Honored

(1) ship gat-search.js ESM like gat-charts.js; (2) v1 ships BOTH inline overlay AND modal/Strg+K; (3) engine-agnostic core + optional Pagefind adapter. App-specific concerns (Bundesland filter, content-type tabs, stemming) stay out of the DS template.
